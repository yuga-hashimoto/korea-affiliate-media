# UI・コンテンツデザイン仕様

## デザイン原則
- トーン: 信頼性の高い比較メディア。旅行ブログと価格比較サービスの中間。落ち着いた余白、明快な数値、広告/出典/更新日時を目立たせる。
- 色: 具体的なカラーパレットはFigma/実画面で決めるが、アクセントは旅を想起させる青緑系。韓国国旗の装飾や特定芸能IPのイメージに依存しない。
- 日本語の可読性: 数字は等幅(tabular nums)、金額の単位、税込/税別、参照日時、送料・税の不明を区別。
- モバイル: 最上部に1文の価値、条件入力、結果カード、比較表、公式リンクと広告表記。PCでは条件と比較表を2カラムで見せる。
- 結論を先に示し、計算過程を折り畳み/詳細に段階開示。比較対象のランキング理由と広告の独立性を明記。
- 外部URLへ誘導するボタンには「〇〇で料金を確認」などの表現、ライブ価格ではない場合は注意書きを付ける。

## コンポーネント
- SiteHeader：ロゴ「総額比較」、旅行/コスメ/比較手法/記事を主導線。
- SearchPanel：旅程/人数/日数/GB、または商品/容量/クーポン条件をフィルタ。
- ComparisonTable：商品、税込価格、送料、税、手数料、総額、確認日、オファー条件。
- TotalCostBreakdown：基本額＋送料＋税＋手数料－クーポン（未確認はUNKNOWN）、計算式。
- SourceStamp：引用元の公式URL、確認時刻、更新期限、注意事項。
- OfferCard：関連商品画像の利用権限、適用条件、広告表記、CTA。
- EditorialNote：比較基準、広告リンクの利用、最終更新日。
- ArticleCard：タイトル、要約、読者が解決する疑問、公開日/更新日。
- Disclaimer：推計/キャッシュ価格/海外通貨/キャンセルの誤解を防ぐ。

## MVP画面の検証基準
- 375pxの狭い画面でも比較条件と総額が最初の2スクロールで理解できる。
- スケルトンや空データで「結果なし」と「取得失敗」を区別。
- CTAの近くに「広告」表示、出典/更新日への簡単なアクセス。
- 公式情報がない場合、適切に比較対象を表示しない/価格不明とする。
- キーボード、読み上げ、ダークモード優先度を検討し、最低でもAA相当を目標。
- 人間が選べる比較条件（人数/日程/容量/クーポン適用）をプリセット化。
- 画像なしでもサイトが成立するテキスト/カードデザイン。

## 実装順序
1. 色・タイポ・余白・UIコンポーネントの小さなデザインシステム
2. トップとカテゴリ、比較表、総額カード
3. 記事テンプレート、SEO、出典表示
4. ローディング/エラー/空状態、アクセシビリティ、レスポンシブE2E
5. 分析に基づくUX改善。広告が主役になる構成は避ける。

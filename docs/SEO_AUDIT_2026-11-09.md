## 2. 原因分析

1. **コンテンツが薄い（最大の原因）**
   - sitemap内の記事39本。本文は実質600〜800字、見出し3〜4個。
   - 「〜が定番です」「公式情報を確認してください」という一般論が中心で、店名・価格・営業時間・アクセス・混雑時間などの固有情報がない。
   - Googleの「クロール済み - インデックス未登録」の典型パターン。ページを増やしても同じ判定になりやすい。
   - 背景: `AGENTS.md` の「裏付けなしの情報を生成しない」を守るため具体情報を避けた結果、SEO上の価値が薄くなっている。**裏付けを取ったうえで具体的に書く**方向へ変える必要がある。
2. **サイトマップとcanonicalの不一致（技術）** — 修正済み。
3. **新規ドメイン・被リンクなし** — 上位表示には通常3〜6ヶ月。0PV自体は公開2日目では異常ではない。
4. **キーワード選定** — 「ソウル カフェ」等の競合が強い一般語に対して独自情報なしで挑んでいる。
5. **カテゴリページがほぼ空** — 記事一覧のみで単体の価値が薄い。

## 3. 今回実施した修正

- `src/app/sitemap.ts`: すべてのURLを末尾スラッシュ付き（canonicalと同一形式）に変更。`withTrailingSlash()` を追加。
- `public/_redirects`: 旧URLの転送先を末尾スラッシュ付きの実URLに変更（308→308の連鎖を解消）。
- `tests/unit/redirects.test.ts`: 転送先の末尾スラッシュを検証するテストを追加。
- `tests/unit/sitemap.test.ts`: sitemapのURL形式・重複なし・記事URLを検証するテストを追加（4件）。
- 検証: `pnpm test` 56件 / `pnpm e2e` 30件 / `pnpm lint` / `pnpm typecheck` / 静的ビルド すべて成功。
- ビルド成果物 `out/sitemap.xml`: 58URLすべて末尾スラッシュ付き、二重スラッシュなしを確認。

## 4. 次の打ち手（優先順）

1. **本番反映**（承認後）: デプロイ → GSCでサイトマップ再送信 → 「クロール済み - インデックス未登録」の「修正を検証」→ 主要10URLのインデックス登録リクエスト。
2. **コンテンツ整理（本質）**: 39本を厳選・統合し、1本3,000字級＋一次情報で確認した具体情報（店名・価格・営業時間・アクセス・混雑・代替案）に作り替える。量産を止める。
3. **キーワード設計**: 競合の強い一般語ではなく、検索意図が明確なロングテール（例: 仁川空港→ソウルの交通、時期別の服装、エリア別の泊まる場所）に集中。
4. **KPI**: 3ヶ月はPVではなく「インデックス率・表示回数・平均掲載順位」で評価。インデックスされない記事はリライト→統合→削除。
5. **E-E-A-T**: 運営者情報・編集方針・出典・更新日は既にあるため維持しつつ、一次情報の具体性で差をつける（体験の捏造はしない）。
